# Metadata Filtering Agent

The following examples demonstrate how SAS Retrieval Agent Manager (RAM) can use custom metadata to filter search results during retrieval.

The collection contains approximately 6,000 IT service management (ITSM) incidents with the following fields:

- incident_id
- description
- assigned_it_person
- category
- severity
- status
- date

## Metadata

The following fields are configured as custom metadata columns in the RAM sources page:

- category (Access, Application, Database, Email, Hardware, Infrastructure, Network, Security, Software)
- severity (Low, Medium, High, Critical)
- status (Open, In Progress, Investigating, Resolved, Closed)
- date
- assigned_it_person

After assigning the desired metadata columns to the source file, you must create and vectorize a collection that the agent will use.

## Approaches

After you create the collection, there are two ways to connect agents to it:
  - [Tool-based experiment with agentic retrieval enabled](./tool_based/):
    - This is often the easiest option when users interact directly with the agent and are unlikely to know the underlying metadata schema.
    - In this approach, the LLM selects the appropriate filters to use based on the user's query.
  - [Template-based experiment](./template_based):
    - This approach gives the caller complete control over retrieval because filters are supplied explicitly to the agent.
    - A template-based approach may be a better fit when retrieval filters must be explicitly controlled, generated by another application, or applied consistently across repeated queries.

## How It Works

For each request:

1. Apply metadata filters.
2. Retrieve matching records.
3. Rank results semantically.
4. Return the most relevant matches.
