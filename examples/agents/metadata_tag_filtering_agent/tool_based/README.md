# Tool-Based Metadata and Tag Filtering

This example uses Agentic Retrieval to automatically infer metadata filters from natural-language requests.

The collection contains approximately 6,000 Information Technology Service Management (ITSM) incidents with metadata fields such as:

- category
- severity
- status
- date
- assigned_it_person

## Configuration

When creating the agent experiment:

1. Add the collection.
2. Enable **Agentic Retrieval** under Collections.

## Example

User:

```text
Show me critical security incidents that are still open.
```

RAM can automatically infer filters such as:

```json
{
  "category": "Security",
  "severity": "Critical",
  "status": "Open"
}
```

before performing semantic search.

## Why Use This Approach?

- No filter syntax required
- Natural-language queries
- Automatic metadata inference
- Better experience for business users
- Faster to configure than a custom filtering template

## Agentic Retrieval vs Template-Based Filtering

Agentic Retrieval is often the easiest option when users interact directly with an agent and are unlikely to know the underlying metadata schema.

A template-based approach may be a better fit when retrieval filters must be explicitly controlled, generated by another application, or applied consistently across repeated queries.
